# 이 형태로 만들 수 있는 플랫폼 (2026-10-11)

## 우리가 가진 '형태' (모든 후보가 같은 부품을 씀)

```
공식 통계·경기 데이터 → 예측 (+80% 범위) → 해시 장부에 '미리 적기' → 개인화 카드 (조회 → 저장 → 공유)
                                                   ↓
                              발표·경기 후 자동 채점 (RPS·오차) → 성적 카드 → 다시 공유
```

부품 5개: ① 예측 엔진 ② 해시 장부 ③ 카드 렌더러 (`town_section.tpl.html`, `badge.py`) ④ 채점기 (RPS·범위 적중) ⑤ 편 가르기 금지 규칙.
새 플랫폼은 대부분 이 부품의 **입력만 바꾸는 일**이라 비용이 작습니다.

## 미적분으로 본 판단 기준

사용자 수 n일 때 가치 V(n).
- **직선형** V ≈ a·n : 사람마다 따로 쓰고 끝남. 꾸준하지만 크지 않음 (V'' = 0).
- **볼록형** V ≈ a·n + b·n² : 사용자가 남긴 예측이 다른 사람에게 가치(순위·비교·집단 예측)가 됨 (V'' > 0). 확장은 여기서만 나옴.
- **오목형** : 고객당 우리 시간이 들어감 (V'' < 0). 현금흐름 바닥으로는 좋음.

## 추천: 하나의 코어, 순서대로 켜기

1. **지금 A (E5)** – 카드 공유가 실제로 일어나는지 4주 안에 확인. 이미 만들어 둠.
2. **다음 B** – 우리 브랜드 "미리 적고, 채점까지 공개"를 **사용자에게 그대로 넘기는** 형태라 가장 잘 맞음.
   통계청 월간 발표(인구동향·고용동향·소비자물가)는 날짜가 미리 정해져 있어 매달 자동으로 '경기'가 생김 → 콘텐츠가 끊기지 않음.
   셈법 모델도 참가자 중 한 명으로 같이 채점됨 (우리가 지면 그것도 공개).
3. **D는 B·C 위에 얹는 수익층** – B에서 성적이 쌓인 사람에게 '검증 배지'를 붙여 주는 것이 곧 공증 상품.
4. **E는 따로 굴리는 현금흐름 바닥** – 같은 엔진, 고객당 월 1시간.
5. **C는 진열장으로만** – 상금·배당 없는 무료 리그, 법률 확인 전에는 확장하지 않음.

## B를 시험하는 가장 싼 방법 (E6 안, 아직 사전등록 안 함)

- 다음 통계청 인구동향 발표 1건을 고름 (월간 출생아·혼인 건수).
- 발표 1주 전, 노션 폼이나 구글 폼으로 "이번 달 출생아 수는?" 예측을 받음 (이름 대신 닉네임, 연락처 안 받음).
- 셈법 예측과 참가자 예측을 장부에 기록 → 발표일에 성적 카드 발송.
- 가설: 참가 20명 이상, 그중 30% 이상이 다음 달에도 참가. 미달이면 B 보류, A만 유지.
- E5 결과(요청 수)를 본 뒤 사전등록 → 확산 경로가 확인된 상태에서 시작.
